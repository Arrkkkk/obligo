## What this project is

Obligo compiles natural-language obligations (from contracts, email, transcripts) into a typed, formally verifiable intermediate representation, detects contradictions between obligations using an SMT solver (Z3), and monitors each obligation against real-world evidence until it's fulfilled or breached.

The differentiator is the compiler (LLM candidate extraction → Lark grammar parse → semantic typecheck) and the verifier (Z3 lowering + unsat-core explanation). Everything else in the stack exists to support those two things. If a proposed change doesn't serve the compiler, the verifier, or making them demoable, treat it with suspicion.

## Local dev environment — DEVIATION FROM BLUEPRINT, READ THIS FIRST

**No Docker on the local machine**, by deliberate choice (not a temporary gap — don't try to "fix" this by installing Docker). This changes how Phase 1 and beyond are executed locally:

- **Postgres:** not run locally. Use a **Neon free-tier branch** (with the `pgvector` extension enabled) as the dev database. Connection string goes in `.env` (git-ignored), never committed.
- **Redis:** not run locally. Use **Upstash's free-tier Redis** (HTTPS/REST-based, no local process needed).
- **The three services run natively**, not in containers: Spring via `./gradlew bootRun`, FastAPI via `uvicorn` in a venv, Next.js via `npm run dev`.
- **Dockerfiles and `compose.yml` still get written** per the blueprint — they're needed for CI image builds (§20.4) and eventual deployment (§20.5) — but they are **not exercised locally** and are not a dependency for local development to work. Do not block any Phase 1 task on "the Compose stack running locally," because it won't be, by design.
- **`make dev` in this project means:** start Spring, start FastAPI, start Next.js natively, pointed at the cloud Postgres/Redis — not `docker compose up`. Write the Makefile target accordingly.
- Docker becomes actually relevant again around Phase 9 (deployment) or whenever CI needs to build and push real images — not before.

- **PyMuPDF text/layout extraction, offsets derived by construction, not post-hoc matching** — `page_text[char_start:char_end] == text` holds by construction for every segment, because the persisted text is literally what produced the offsets. **IR Compiler checkpoint (§21 Phase 4) — `apps/brain/src/obligo_brain/compiler/ir_compile.py` written and proven, no DB, no LLM, no network. This is the deterministic bridge between the Extractor/Span Grounder checkpoint's `GroundedCandidate` and the parser/typechecker checkpoint's `parser.parse()` — this checkpoint is DSL construction and classification only.**
- **`compile_candidate(candidate: GroundedCandidate) -> ast.Obligation | CompileFailure`**, plus a batch form `compile_candidates()` mirroring `ground_candidates()`'s partition shape (every input ends up in exactly one of the two output lists — nothing silently dropped). Pure function, same "do NOT use LangGraph when the flow is linear" reasoning already applied to the Extractor/Grounder — and deliberately NOT the parse-error repair loop (§6.3 stage 3's own, separate, not-yet-built failure path): no retry, no model call, classify-or-fail once.
- **Two real classification problems, both resolved by deterministic pattern matching, not a second LLM call** — Standing Principle 2 applies directly, since which of the five frozen `Temporal` forms an obligation gets, and what its extracted duration/date/trigger actually is, determines the compiled IR's meaning, not a draft:
  - `temporal_raw` → one of the five frozen `Temporal` forms, via five regexes each anchored to its own distinct leading keyword (`within`/`by`/`every`/`during`/`before`|`after`) — a closed-vocabulary problem structurally identical to what the grammar already does for `ACTION`/modality, not open-ended NLU. Because the five keywords are mutually exclusive leading tokens, no two forms can ever match the same phrase (`AMBIGUOUS_TEMPORAL` is structurally unreachable under this design and wasn't built as a separate reason).
  - `condition_raws` → each entry becomes exactly one `AtomPredicate` wrapping its raw text verbatim; multiple entries become multiple separate `IF "..."` clauses (implicit conjunction), never structured by detecting `AND`/`OR`/`NOT` inside a single string — unlike the temporal keyword vocabulary, boolean connectives in free legal text are genuinely ambiguous (`"not later than"` contains "not" but isn't a boolean negation), a real misclassification hazard a closed-vocabulary regex can't safely resolve. Because every string is trivially a valid atom, there's no failure mode here at all.
- **Unmappable `temporal_raw` rejects the whole candidate (`CompileFailureReason.UNMAPPABLE_TEMPORAL`), never silently compiles with `temporal=None`** — same "never silently drop" precedent as `NESTED_FIELD_NOT_IN_SPAN` discarding a whole candidate rather than patching one field. Dropping just the temporal field would silently understate the obligation (a timed "notify within 5 days" quietly becoming an untimed "notify" is a different, weaker obligation), and there's no AST slot to hold "has a temporal phrase, couldn't classify its shape" — `Temporal` is frozen at exactly five variants. A `GroundedCandidate` whose `temporal_raw` is genuinely `None` (no temporal phrase extracted at all) compiles `temporal=None` correctly — that's not a drop.
- **`modality`/`action`/`object_class` are only lightly, deterministically canonicalized** (case/whitespace normalization) and then left for the real grammar to validate as the closed-taxonomy authority — re-checking `ast.MODALITIES`/`ast.ACTIONS` here would duplicate what `grammar/obligation.lark`'s own terminals already enforce; any mismatch surfaces as `CompileFailureReason.PARSE_ERROR` with the parser's own precise diagnostic.
- **Ordering relative to `typecheck.py`: strictly before, never interleaved**, and this checkpoint changes nothing about tenant-scoped party-resolution timing. `compile_candidate()` opens no DB connection and calls `tenant_scope()` nowhere — pure, like `ground_candidates()`. Party aliases pass through unchanged as quoted strings; `parser.py` still turns them into `UnresolvedParty`; `typecheck.py`'s existing `tenant_scope()`-scoped `symbols.resolve_party()` call runs unchanged, strictly afterward.
- **A real, named scope limit: `DURING` only accepts two ISO-8601 date literals, not a defined-term alias on either side** (`"during the Term"` rejects, `UNMAPPABLE_TEMPORAL`) — splitting one free-text interval phrase into two separate alias termini deterministically is genuinely ambiguous, unlike `WITHIN`/`BY`'s single trailing phrase. Falls through loudly rather than guessing a split.
- **Real bug found and fixed by adversarial testing against realistic (non-textbook) phrasing, not caught by the original hypothesis/fixture suite:** `"by 2026-01-01."` — a trailing sentence-terminating period, exactly what a verbatim quote of the end of a real sentence looks like — silently downgraded a genuinely resolvable date into an unresolved alias (`UnresolvedDate(raw="2026-01-01.")` instead of `ResolvedDate("2026-01-01")`), a **silent corruption**, not a loud failure — the same category of bug this project's span-grounding discipline exists to catch, just one layer downstream of it. `EVERY`/`DURING` had the identical anchor problem, manifesting as safer-but-still-wrong under-rejection instead of corruption. **Fix scoped narrowly, not as a blanket period-strip:** trailing-period tolerance was added only at the three fixed-format token boundaries (`BY`'s date check, `EVERY`'s unit anchor, `DURING`'s second date anchor) — every one a closed, unambiguous format that can never legitimately contain a trailing period itself. Free-text trigger/alias capture (`WITHIN`'s/`RELATIVE`'s trigger, `BY`'s alias fallback) was deliberately left untouched and verified untouched (`"within 5d of Corp."` still preserves `"Corp."` verbatim in trigger text, not stripped) — an abbreviation's period is meaningful and must stay byte-verbatim, per this codebase's span-grounding discipline; only a token with zero legitimate use for a trailing period gets the tolerance.
- **The explicit lesson, not just the bug:** this checkpoint was first built and tested at `/effort medium`, using hypothesis-generated structural variation (units, amounts, arbitrary trigger text) plus hand-picked textbook phrasings ("within 5 business days of X") — and that suite passed clean while still shipping the silent-corruption bug above. A second adversarial pass, specifically testing realistic verbatim-quoted phrasing (trailing punctuation, non-canonical synonyms like "no later than"/"on or before"/"prior to", spelled-out numbers, "calendar days") found it immediately. **Regex/classification code whose input is real extracted document text — not just structurally-varied synthetic input — needs adversarial-phrasing testing as part of its first pass, not as a follow-up prompted by a direct question.** Same standing as the Extractor/Span Grounder checkpoint's real-cassette-over-synthetic-only discipline; apply it by default to any future deterministic classifier over LLM-extracted text (e.g. a future date/currency/jurisdiction normalizer), not only when asked.
- **Realistic phrasings confirmed correctly out of scope, not bugs** — `"no later than"`, `"not later than"`, `"on or before"`, `"prior to"`, spelled-out numbers (`"thirty (30) days"`), `"calendar days"`, and bare recurrence words (`"annually"`) all correctly reject as `UNMAPPABLE_TEMPORAL` rather than being silently misclassified, consistent with this checkpoint's own "strict over loose" decision — pinned as regression tests (`test_realistic_out_of_scope_phrasings_reject_rather_than_misclassify`) so the boundary stays a tested, intentional decision rather than an unexamined gap. Widening coverage to include these is real future scope for whoever next touches this classifier, not something to add quietly.
- **Proven with unit tests per temporal form/failure path plus two hypothesis round-trip properties** over the `WITHIN`/`EVERY` duration classifier across all 6 units (`tests/compiler/test_ir_compile.py`, 34 cases) — the classifier's own analog to `test_properties.py`'s round-trip property for the grammar itself. **Parse-error repair loop checkpoint (§21 Phase 4) — `apps/brain/src/obligo_brain/graphs/repair.py`, `prompts/repair/v1.yaml`, `apps/core/.../V18__create_compile_quarantine.sql`. The first genuinely branching logic in the extraction pipeline. Still no LangGraph, deliberately — see below. No Z3, no Critic, no Linker.**

- **LangGraph deliberately NOT introduced, for the third time — with a falsifiable trigger written down so the next checkpoint doesn't re-argue it from scratch.** `state.py`/`extraction.py` had both pre-committed to "LangGraph gets introduced at whichever future checkpoint adds the first real conditional edge (most likely the parse-error repair loop)"; that prediction came due here and was declined on the merits. The cycle is one node with one back-edge and a bounded counter — a `while` loop expresses it completely. §6.8's own three justifications are either already satisfied (`agent_runs.node_trace` is the trace §6.8 says the graph maps 1:1 *to*; per-node retry is implemented here with domain-specific hint derivation a generic retry can't supply) or not yet needed (crash-resume: the whole loop is one synchronous call in one process). Lives in `graphs/` rather than §6.1's suggested `compiler/repair.py` because it makes LLM calls and DB writes, and `compiler/` is deliberately I/O-free — a documented deviation.
- **Blueprint §6.3 stage 1 assumes "LLM → DSL"; this codebase does "LLM → JSON candidate" + deterministic DSL construction, so "feed the parser error back" needed translating rather than implementing literally.** Handing the model a Lark diagnostic about a string it never wrote would teach it to author DSL, routing around both the deterministic bridge and the grounding gate. Instead the parser's verdict is translated into field-level `RepairHint`s about the JSON the model did write. **That translation is exhaustive, not best-effort:** tracing every path from `_build_dsl` to the grammar (`_q()` is `json.dumps` so every `ESCAPED_STRING` slot is well-formed by construction; `segment_id` comes from the DB; offsets come from the grounder; `format_confidence`/`_format_amount`/`_unit_token`/`_DATE_RE` guard the rest), **exactly three fields can ever cause a `PARSE_ERROR`: `modality`, `action`, `object_class`.** All three are *classification* fields, none is span-grounded — which is precisely what makes repairing them safe. The raw Lark message is recorded in `agent_runs.node_trace` and never sent to the model.
- **No actionable hint ⇒ no model call.** An unexplainable `PARSE_ERROR` quarantines immediately with zero LLM calls; a repair prompt with no actionable hint is a coin flip that costs money and a rate-limit slot. Same "strict over loose" posture `ir_compile.py` takes on `DURING`.
- **A repair is structurally incapable of fabricating a quote.** The repaired candidate is built by copying the original `LLMCandidate` and overriding **only fields that carried a hint**; `span_text`, the aliases, `object_raw_text`, `condition_raws` and `confidence` are never read from the model's response at all. Standing Principle 2 applied to a retry: don't trust the model to obey an instruction that determines correctness — make disobeying it inert. The one repairable field that *is* grounded, `temporal_raw`, gets no bespoke check; the repaired candidate goes back through `ground_candidates()` in full, which stays the sole authority (a rewrite is caught as `NESTED_FIELD_NOT_IN_SPAN` and quarantined as `REPAIR_BROKE_GROUNDING`). A `null` `temporal_raw` is never accepted — that would "fix" the compile by silently turning a timed obligation into a weaker untimed one.
- **`UNMAPPABLE_TEMPORAL` is included but is honestly expected to be mostly unrepairable, and that is written into the code rather than discovered later.** `temporal_raw` must stay verbatim, so if the source says "no later than thirty (30) days after the Effective Date" *no substring will ever match* — the real fix for that class is widening `ir_compile._classify_temporal`'s vocabulary, already named as future scope there. The one genuinely repairable shape is **over-capture** (narrowing to a shorter verbatim substring that is a clean timing phrase). **Measure the real success rate when the eval harness (§19.7) exists; if it lands near zero, demote `UNMAPPABLE_TEMPORAL` to quarantine-immediately.** Worth noting the test fixture for this had to be chosen against the real classifier rather than assumed: the obvious-looking `"within 30 days of X, as extended"` actually compiles fine (WITHIN's trigger capture is `.+`) — the real over-capture case is `"every 30 days during the Term"`, since `_EVERY_RE` is end-anchored.
- **Batched by segment, not by candidate** — one call carries every currently-failing candidate with its own index and hints, the next carries only those still failing. `max_repairs=2` per *candidate* would cost up to 20 extra calls for a 10-candidate segment against a free tier that is rate-limited per minute and per day (§13.7/§13.8), and §6.10's budget-enforcing router isn't built. An attempt that changes nothing at all short-circuits the loop (`REPAIR_MADE_NO_PROGRESS`) rather than paying for a temperature-0 repeat of an identical payload.

- **`input_hash` had to diverge for repair, and the divergence is a real hazard avoided, not a style choice.** `extraction.py`'s `sha256(segment_id : prompt_hash : model_id)` would make two different failing candidates *from the same segment* collide on one `input_hash` — and V17 records that column as the key for §6.10's future content-hash response cache, so a collision would serve one candidate's repair for another's. `repair_input_hash()` hashes the rendered `system`/`user`/`model_id` instead. The general rule is "hash the actual rendered call inputs"; extraction's formula is a valid *special case* (segment_id + prompt_hash fully determine its rendered message). Documented in both places rather than left as two unexplained formulas.

Deliberately one-directional, not a symmetric pair, and that's a real semantic distinction, not an oversight: `RETAIN`/`WITHHOLD` describe a continuous state held throughout a window (the same shape as a `MUST_NOT`'s own forbidding window), `DELETE`/`DISCLOSE` describe a point-in-time act — "must delete by March 1" does not forbid retaining right up until the deletion, so the reverse direction is deliberately absent and pinned as its own regression test (`test_antagonism_is_not_symmetric_must_not_retain_does_not_imply_prohibition_on_delete`, `test_delete_must_never_implies_a_prohibition_on_retain`). Same atom text across two different obligations' conditions is the same Z3 variable, which is what lets `IF "X"` in one obligation and `IF NOT "X"` in another genuinely contradict each other (`CONDITION_CONTRADICTION`, `tests/verifier/test_verify.py::test_condition_contradiction_without_any_modal_conflict`) — and, separately, what lets a `.cond` fact and a `.window`/`.prohibition` fact be found as two *independent* minimal cores in one solve when both are genuinely present (`test_condition_contradiction_isolated_no_temporal_overlap_at_all`, which real-world both contradicts on conditions and conflicts modally, and the multi-core enumeration correctly reports both).

Every fact is asserted as `Implies(selector, constraint)`, with the selector passed as an *assumption* to `solver.check()` per call rather than permanently asserted true; this is what makes deletion-based minimization and multi-core search both possible by varying which selectors are active per call, reusing one `Solver` object throughout a group's search, bounded at 5 cores total and a 120s timeout (`Z3_TIMEOUT_MS`, matching blueprint §4.2's own constant) that surfaces as `VerificationResult.timed_out_groups`, never a silently-claimed SAT.

## Standing principles (do not violate these without asking)

1. **The system must be demoable at every commit.** Don't leave the stack in a broken state overnight.
2. **Deterministic core, probabilistic edge.** Anything a parser, typechecker, or solver can decide must not be decided by an LLM. If you're about to have a model output something that determines correctness (not just a draft/candidate), stop and ask.
3. **One trust boundary, three enforcement layers** for tenant isolation: gateway → application (`TenantConnectionPreparer` AOP setting the RLS GUC per-transaction + `@PreAuthorize`) → database (RLS, `FORCE`d, fail-closed). All three, always. Note: there is no JPA/Hibernate anywhere in `apps/core` — it's `JdbcTemplate` throughout, so "Hibernate `@Filter`" (as blueprint §10.9's diagram depicts for Layer 2) does not apply to this codebase; Layer 2 is the AOP described above, not a Hibernate filter.
4. **Every LLM output is untrusted input** — including, especially, when it originates from a document the user uploaded. Never concatenate document text into a system prompt.
5. **Prefer deleting a technology over adding one.** If a task seems to need a new piece of infrastructure, check the "explicitly deferred" list below first — it's probably already been considered and rejected for now.

## Non-negotiable engineering rules

- **Idempotency:** every mutating endpoint accepts `Idempotency-Key`. Every response carries `X-Request-Id`.
- **Tenant isolation:** every tenant-scoped table has `org_id` and an RLS policy from the moment it's created — not retrofitted later. Its repository must implement `TenantScopedRepository` (`apps/core/.../platform/tenancy/`), which `TenantIsolationArchitectureTest` enforces at build time: every public method must be `@Transactional`, and no raw `DataSource`/`Connection` field is allowed. This proves the precondition for isolation, not isolation itself — the actual guarantee is still the RLS policy + `TenantConnectionPreparer`, so write and test each new repository's isolation behavior for real, the ArchUnit rule alone isn't sufficient.
- **No `localStorage`/`sessionStorage` for tokens.** Access tokens live in JS memory only. Refresh tokens are `HttpOnly` cookies.
- **Migrations are immutable once merged.** Corrections are new migrations, never edits to old ones. Use expand/contract for anything destructive.
- **No raw SQL string concatenation, ever.** Parameterized queries only, in both Java and Python.
- **Extraction/compiler output must cite a verbatim source span.** If a candidate obligation's span text doesn't literally appear in the source segment, discard it — don't try to "fix" or reinterpret it.
- **Prompts are versioned files, not inline strings.** Once Phase 4 starts, every prompt lives in `brain/prompts/` with a version and is never edited in place — bump the version.
- **Every LLM call records `model_id`, `prompt_version`, cost, and latency.** Without this, nothing about the AI pipeline is reproducible or debuggable later.
